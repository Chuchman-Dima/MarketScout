# Документація: парсер Auto.RIA

Скрипт збирає оголошення про легкові авто (`category_id=1`) через `developers.ria.com` і складає їх у плаский CSV для ML.

## Як це працює

1. **Пошук**: `/auto/search` віддає 100 ID за сторінку.
2. **Деталі**: для кожного нового ID йде запит `/auto/info`, JSON перетворюється на один рядок (`parse_car_entry`) і одразу дописується в CSV (`save_entry`).
3. **Стан**: після кожної сторінки номер зберігається в `parser_state.json`, тож після зупинки збір продовжується з того ж місця.
4. **Фото**: після збору `download_pending_photos` паралельно (8 потоків) качає головні фото з CDN. Це не витрачає бюджет API.

**Ліміти:** `MAX_REQUESTS = 98000` (пошук і `/info` рахуються в один бюджет), тайм-аут 10 с, пауза 1 с між авто і 1.5 с між сторінками. При `429` скрипт чекає `Retry-After` і **не повторює** запит.

**Файли** (у `data/`): `new_cars_dataset_2.csv` (датасет), `parser_state.json`, `parser.log`, `photos/`. Ключ береться з `.env` (`MY_API_KEY`).

## Функції

| Функція | Що робить |
|---|---|
| `safe_get` | Дістає ключ зі словника; якщо словника немає або значення `None`, повертає default |
| `fetch` | GET із тайм-аутом; `None` при мережевій помилці або 429 |
| `load_state` / `save_state` | Читає й пише останню сторінку пошуку |
| `get_collected_ids` | ID, які вже є в CSV (для пропуску дублів) |
| `run_collection` | Основний цикл: сторінка пошуку, потім деталі нових ID, лог |
| `parse_car_entry` | Сирий JSON перетворюється на словник фіч |
| `save_entry` | Дописує один рядок у CSV (`utf-8-sig`) |
| `download_pending_photos` | Докачує фото для рядків із порожнім `Main_Photo_Path` |

## Фічі (колонки CSV)

Значення за замовчуванням, якщо поля немає у відповіді: `0` для чисел, `''` для рядків, `False` для булевих. Позначка ⚠️ означає, що зміст виведено з назви поля, тож звір із документацією RIA.

| Колонка | Що означає |
|---|---|

## На що звернути увагу

- **Пропуски маскуються нулями.** Відсутнє значення й справжній `0` (наприклад, ціна чи пробіг) виглядають однаково. Перед навчанням варто замінити підозрілі `0` на `NaN`.
- **Можливий витік цілі.** Якщо ціль `Price_USD`, то `Price_UAH`, `Price_EUR` майже дублюють її, а `Is_Sold`, `Views_*`, `Bookmarks_Count`, `Top_*` описують стан оголошення після публікації.
- **Ідентифікатори не для моделі:** `ID`, `UserId`, `VIN`, `Ad_Link`, `Main_Photo_*`, `PartnerId`.
- **Пари `*_Name` / `*_Id`** несуть ту саму інформацію, тож достатньо однієї з двох.
- **`Age = 0`** буває і для нового авто, і для некоректного року. Розрізнити їх за самою колонкою не вийде.
- **NLP-фічі** шукають підрядок, тому «торг» знайдеться й у слові «торгівля». Це груба евристика.
